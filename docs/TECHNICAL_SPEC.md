# Техническое задание: Winter Desktop

> Исходный текст ТЗ, предоставленный заказчиком. Хранится в репозитории для
> трассируемости решений. Ссылки на разделы ТЗ используются в `ARCHITECTURE.md`,
> `ROADMAP.md` и `TASKS.md` (например, §3.2 — накопление снега).

## 1. Общая информация

**Название проекта:** Winter Desktop
**Тип продукта:** Бесплатное настольное приложение с интерактивными зимними эффектами.
**Основная платформа:** Windows 10 и Windows 11, 64-bit.
**Перспективная платформа:** macOS 12+.
**Модель распространения:** Бесплатная, без подписок, лицензий и обязательной регистрации.

### 1.1. Цель проекта

Разработать приложение для Windows, которое создаёт реалистичную интерактивную зимнюю
атмосферу поверх рабочего стола и открытых окон.

Приложение должно обеспечивать:

- Реалистичную анимацию падающего снега.
- Накопление снега на границах окон и нижних поверхностях.
- Взаимодействие пользователя со снегом.
- Создание снежков и снеговиков.
- Дополнительные декоративные эффекты.
- Работу с несколькими мониторами.
- Минимальное потребление системных ресурсов.
- Возможность управления через системный трей.

### 1.2. Основные принципы

1. Все функции доступны бесплатно.
2. Приложение работает локально, без обязательного подключения к интернету.
3. Не требуется учётная запись пользователя.
4. Не собираются персональные данные.
5. Пользователь самостоятельно управляет всеми эффектами.
6. Приложение не должно мешать работе с другими программами.
7. Архитектура должна предусматривать добавление новых эффектов и поддержку macOS в будущем.

## 2. Технологический стек

OpenCode должен самостоятельно оценить совместимость технологий и выбрать наиболее
надёжную реализацию.

Предпочтительный стек для Windows:

- C# / .NET 8 или более новая LTS-версия.
- Win32 API для взаимодействия с окнами Windows.
- Direct2D / Direct3D для аппаратного ускорения графики.
- WPF или WinUI 3 для интерфейса настроек.
- SkiaSharp допускается для отдельных графических компонентов.
- JSON для локального хранения настроек.
- MSIX или Inno Setup для создания установщика.

Важные требования:

- Не использовать браузер в качестве основы приложения.
- Не создавать тяжёлую Electron-оболочку.
- Не использовать платные библиотеки и SDK.
- По возможности использовать бесплатные библиотеки с открытым исходным кодом.
- Разделить графический движок, бизнес-логику, настройки и системную интеграцию
  на независимые модули.

## 3. Функциональные требования

### 3.1. Система снегопада

Реализовать систему генерации и анимации снежинок.

Режимы:

- Лёгкий снег.
- Обычный снег.
- Метель.

Настройки:

- Интенсивность снегопада.
- Размер снежинок.
- Скорость падения.
- Скорость и направление ветра.
- Разброс снежинок.
- Прозрачность.
- Разнообразие форм снежинок.
- Вероятность появления крупных снежинок.

Поведение:

- Снежинки должны двигаться с естественной физикой.
- Должны учитываться ветер и инерция.
- Снежинки должны взаимодействовать с границами окон и поверхностями.
- Не должно быть резких скачков положения объектов.
- При изменении настроек эффект должен обновляться без перезапуска приложения.

### 3.2. Накопление снега

Реализовать накопление снега на:

- Верхних границах открытых окон.
- Нижних границах окон.
- Панели задач.
- Видимых элементах рабочего стола.
- Поддерживаемых виджетах и других поверхностях.

Требования:

- Снег формирует визуально естественные сугробы.
- Толщина сугробов зависит от интенсивности и продолжительности снегопада.
- Снег должен перемещаться вместе с соответствующим окном.
- При закрытии окна снег должен корректно удаляться или перераспределяться.
- При перемещении и изменении размеров окон накопленный снег должен сохранять
  логическую привязку.
- Предусмотреть ограничение максимального количества накопленного снега.

Важно: приложение должно получать только необходимую информацию о геометрии окон.
Необходимо исключить чтение содержимого окон, текста, изображений и пользовательских данных.

### 3.3. Взаимодействие со снегом

Реализовать два основных инструмента.

**Варежка:**

- Пользователь проводит курсором по снегу.
- Снежный покров постепенно смахивается.
- Возможность выбирать силу воздействия.
- Реалистичная реакция частиц на движение курсора.

**Лопата:**

- Полное удаление накопленного снега.
- Возможность очистки отдельного окна.
- Возможность очистки всех мониторов.

Дополнительно:

- Анимация разлета снега при взаимодействии.
- Корректное взаимодействие с несколькими слоями снега.

### 3.4. Снежки и снеговики

Реализовать возможность:

- Собирать снег в снежный шар.
- Катать снежный шар курсором.
- Увеличивать размер шара при катании.
- Размещать снежки на поверхностях.
- Собирать снеговика из нескольких шаров.
- Перемещать снеговика.
- Удалять отдельные снежки и снеговиков.

Физика:

- Учитывать массу и размер объектов.
- Реализовать столкновения.
- Учитывать гравитацию.
- Предусмотреть устойчивое положение на поверхности.
- Не допускать проваливания объектов сквозь окна и границы экрана.

### 3.5. Гирлянды

Реализовать декоративные гирлянды на границах окон.

Возможности:

- Включение и выключение гирлянд.
- Размещение огоньков вдоль верхней границы окон.
- Мерцание огоньков.
- Последовательное включение и выключение.
- Эффект бегущей волны.
- Настройка скорости анимации.
- Настройка яркости.
- Настройка цвета.
- Настройка плотности огоньков.

Гирлянды должны корректно перемещаться вместе с окнами.

### 3.6. Живые зимние обои

Реализовать отдельный декоративный режим.

Предусмотреть минимум две сцены:

1. Домик в зимнем лесу.
2. Крыльцо загородного дома.

Возможности:

- Анимированный свет в окнах.
- Мерцание гирлянд.
- Дым из трубы.
- Движение отдельных элементов окружения.
- Переключение между сценами.
- Включение и выключение режима одной кнопкой.
- Возможность отключить сцены без удаления текущих обоев пользователя.

Сцены должны работать как отдельный слой и не должны необратимо менять обои Windows.

Графические материалы должны быть оригинальными или иметь лицензию, допускающую
свободное использование.

### 3.7. Снегоуборщик

Реализовать анимированного персонажа или транспортное средство, которое периодически
очищает накопленный снег.

Варианты:

- Обычный трактор.
- Ретро-трактор.
- Снегоход.
- Пингвин с лопатой.
- Пользовательское изображение.

Поведение:

- Персонаж появляется при достижении заданного количества снега.
- Двигается вдоль нижней части экрана.
- Убирает накопленный снег по мере движения.
- Исчезает после завершения уборки.
- Поддерживает несколько мониторов.

Пользовательские изображения:

- Загрузка PNG, JPG, WEBP.
- Возможность изменения размера.
- Сохранение пропорций.
- Возможность удаления пользовательского изображения.
- Проверка формата и размера файла.

Отдельно предусмотреть возможность загрузки собственного изображения на отвал
снегоуборщика.

### 3.8. Системная интеграция

Реализовать:

- Запуск приложения вместе с Windows.
- Иконку в системном трее.
- Управление через контекстное меню трея.
- Быстрое включение и отключение снега.
- Полную паузу всех эффектов.
- Быструю очистку снега.
- Открытие настроек.
- Полное завершение приложения.

Клики пользователя должны проходить к расположенным под визуальными эффектами окнам.

Для этого использовать корректную реализацию прозрачных окон и click-through через
Win32 API.

При необходимости временно отключать click-through для взаимодействия пользователя
со снегом и инструментами.

### 3.9. Несколько мониторов

Приложение должно поддерживать:

- Один монитор.
- Два монитора.
- Три и более мониторов.
- Разное разрешение мониторов.
- Разное масштабирование DPI.
- Различное расположение мониторов.
- Изменение конфигурации мониторов во время работы.

Настройки:

- Снег на всех мониторах.
- Снег только на выбранных мониторах.
- Отдельная интенсивность снегопада для каждого монитора.
- Независимая очистка снега на мониторах.

### 3.10. Автоматическое управление производительностью

Реализовать систему адаптивной производительности.

Требования:

- Использование аппаратного ускорения.
- Ограничение частоты кадров.
- Ограничение количества одновременно существующих частиц.
- Снижение интенсивности эффектов при высокой нагрузке.
- Уменьшение нагрузки при работе от аккумулятора.
- Автоматическая пауза при переходе в полноэкранное приложение или игру.
- Приостановка неактивных анимаций.
- Возможность ручного выбора уровня производительности.

Предусмотреть три профиля:

- Экономичный.
- Сбалансированный.
- Максимальное качество.

## 6. Архитектура проекта

Разделить приложение на следующие независимые модули:

1. Core — основная логика приложения.
2. SnowEngine — генерация и физика снега.
3. WindowTracker — отслеживание окон Windows.
4. OverlayRenderer — отображение прозрачных слоёв.
5. InteractionEngine — взаимодействие курсора со снегом.
6. SnowmanEngine — снежки и снеговики.
7. DecorationEngine — гирлянды и живые сцены.
8. SnowCleaner — логика снегоуборщика.
9. MonitorManager — управление мониторами.
10. PerformanceManager — управление производительностью.
11. SettingsManager — настройки и локальное хранение.
12. TrayManager — управление через системный трей.
13. UI — пользовательский интерфейс.

Модули должны иметь чёткие интерфейсы и минимальную связанность.
